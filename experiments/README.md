## 题目与输入

题目是50人软件公司的内部文档问答选型：DeepSeek API还是本地Qwen，第一版怎样实现、怎样更新资料与隔离项目权限。

- [question.txt](question.txt)：所有组相同的研究题。
- [brief.txt](brief.txt)：所有组相同的5000份文档、10人使用、双24GB显卡、单后端工程师与两周期限。
- [answers.txt](answers.txt)：首轮澄清后明确的实验场景答案，全部组都收到。它们由实验者设定，不是Zero或真实客户的口述。
- [style_sample.txt](style_sample.txt)：只有B使用的自写语态样本，明确不是客户原稿，也不作为事实来源。

模型请求名与返回名均为 `deepseek-flash`。[当天官方模型页](https://api-docs.deepseek.com/quick_start/pricing/)将其对应到 DeepSeek-V4.1-Flash-1017；API返回的是别名，不是不可变权重哈希。

统一初始查询上限3、有效页面上限6、最多1轮缺口补查、每次模型输出上限16384 tokens。B实际先做1个英文查询，再针对缺口补了2个中文查询；3不是必须凑满的初始查询数。初稿搜索抓取使用免Key后端，没有调用付费搜索API。

## 这些数字能说明什么

本次A串行思考版更慢，但A并发非思考版自己就降到了51.1秒；不能把全部速度差归给“定向取证”。B虽然调用次数更多，仍在33.4秒完成。总调用数、串行链长度、每次生成多少token，是不同的量。

A串行版正文4736字符，A快速版10017字符，B为2929字符。不能总结成“思考越多正文必然越长”：这次A快速版的正文反而最长，A思考版多花的是推理token。所有数值来自运行文件，Output已包含Reasoning，不能重复相加；费用只给官方峰谷单价推算范围，不冒充扣费账单。

这不是单变量因果实验：A两个配置同时改变思考与并发；A/B还改变了澄清、查询、材料处理、补查、风格样本和写作。搜索结果不是固定语料，顺序运行会受到网页缓存与API前缀缓存影响；成功抓页的缓存命中分别为0、1、1。没有盲评或多题重复采样，不能用于给DeepSeek、GPT-Researcher、LangChain或WorkBuddy排名。

A串行版完成后，本项目还修正了段落编号与技术URL校验，并补记模型输出；后续快速组使用修正后的代码及新增的来源链接格式提示。两份[串行组源码哈希](2026-10-20/source-manifest-a-thinking.json)和[快速组源码哈希](2026-10-20/source-manifest-fast-arms.json)分别保存。这也是它只能称工程摸底对照、不能称严格同版本消融的原因。

## 读稿后的实际观察

A没有被故意写成错稿：串行版能区分用户场景与外部事实，知道第三方价格不应直接充当预算；主要建议却放在最后的“展望”，前面先走固定四节目录。快速版延续这个目录，扩写更明显。

B把建议放在开头，并能按缺口补查，但还有问题：

- “本地Qwen两周内不是一个人的活”这样的标题，超过了本次证据能支持的范围；这应作为工程风险判断收窄，不能当普遍事实。
- 部分具体工程建议来自模型综合，不是引用网页逐项验证过的方案。原文匹配与引用ID存在性检查不能代替判断“这条引文支持这句话吗”。
- 局部修订确实只改了P1，但第一次要求约150字，实际仍是282字符，没有严格服从篇幅。这里保留原始结果，没有偷偷人工改成达标样稿。
- 补查中模型自行选了Qwen2.5关键词，说明若任务是“2026最新型号全面选型”，应在简报里明确型号与时间范围。本题不能冒充当前全模型榜单。

这个原型提供的是继续改稿和补证据的接口，不把一次生成当自动验收。上述不足也没有用额外模型反复润色到看不出痕迹。

## 失败记录也保留

[attempts.json](2026-10-20/attempts.json)列出调通过程中的原始运行，重复复制的A目录没有重复计费。单独的首次连通性探针为7 input、1 output token，不在运行表中。

- 环境里原本已有另一个API变量，首个应用请求返回401；先前直接读项目.env的探针成功。现改成项目.env优先，未将密钥写入日志。
- B在答案不足时返回 `needs_alignment`，没有自动越过真实澄清；给出场景答案后继续。
- 8192预算下A写作触发 `finish_reason=length`，程序报失败；之后三组统一上限16384。失败耗时130.545秒和完整usage保留在 [a-8192-truncated](2026-10-20/attempts/a-8192-truncated/metrics.json)。
- A快速版一度因段落ID校验失败；修正为程序分配段落ID。另一次把真实技术端点URL误判成伪造来源；修正为区分裸技术端点和来源超链接。这两项是本项目的实现问题，不应写成模型“不会研究”。相关 [ID失败](2026-10-20/attempts/a-fast-paragraph-id/failure.json) 与 [URL失败](2026-10-20/attempts/a-fast-url-validator/failure.json) 留存。
- 免费搜索最初的Bing RSS降级会把业务长问题变成品牌首页。实测DuckDuckGo Lite可用后置于首选；不保证换网络后仍有相同结果。

## 重跑与导出

先按主README准备.env与虚拟环境，再运行（请选一个新的目录，不覆盖旧实验）：

```bash
bash experiments/run_demo.sh runs/my-repeat
```

脚本依次跑三组与一次P1修订。若某组失败会停下，失败调用仍写metrics与events，不会静默跳过去。

```bash
python experiments/compare.py runs/my-repeat experiments/my-repeat
python -m deep_research export --run-dir runs/my-repeat/b-fast --output experiments/my-repeat/b-fast
```

其他组同样用export导出。原始页面、完整渲染Prompt、修正后新增的模型输出日志只在被忽略的runs目录；公开目录保留报告、metrics、events和有限证据摘录。不要手动复制整个运行目录到公开仓库。
